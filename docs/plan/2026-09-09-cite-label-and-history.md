# 인용에 출처 표시 · ↑↓ 로 이전 프롬프트

두 가지를 설계한다. 서로 무관하지만 둘 다 입력·출력의 '읽기 쉬움' 문제다.

---

# 1. 인용 번호에 출처를 같이 보여준다

> **구현 완료 (2026-09-09).** 아래 A 안 그대로 갔다. 설계와 달라진 점 하나 —
> 도메인이 붙으면 위첨자를 푼다(`.gt-cite[data-wide]`). `[1 zdnet.co.kr]` 을
> 0.78em 위첨자로 얹으면 읽을 수가 없다.

지금은 `[1]` 뿐이라 **호버하기 전에는 어느 링크인지 모른다.**
([2026-09-08 인용 링크 전환](../issue/2026-09-04-citation-markers-shown-raw.md) 이후 상태)

## 무엇을 붙일 수 있나

`refs` 에 이미 들어 있는 것 — 실측으로 확인된 값들이다.

| 필드 | 실제 값 예시 |
|---|---|
| `attribution` | `ZDNet Korea` · `IT조선` · `미래를 보는 창 - 전자신문` · `고용노동부` |
| `title` | `삼성전자, 2분기 HBM 점유율 33%로 급등…SK하이닉스와 격차 축소 - ZDNet korea` |
| `url` | `https://zdnet.co.kr/…` · `https://it.chosun.com/…` · `https://www.etnews.com/…` |

`title` 은 문장이라 인라인에 못 쓴다. 남는 건 `attribution` 과 **도메인**이다.

## 안

### A. 도메인 — `[1 zdnet.co.kr]` ← 추천

```
- 삼성전자 HBM 점유율이 오릅니다. [1 zdnet.co.kr]
- 통신 3사가 청사진을 공개했습니다. [2 it.chosun.com]
```

- **길이가 예측 가능하다.** 대부분 10~16자
- 터미널에서 도메인은 자연스럽다. 주소창을 읽는 것과 같은 감각
- `www.` 는 뗀다. `www.etnews.com` → `etnews.com`
- 호버 title 에는 지금처럼 `미래를 보는 창 - 전자신문 — https://…` 를 남긴다

### B. 발행처 — `[1 ZDNet Korea]`

- 사람이 읽기엔 더 낫다
- 그러나 **길이가 들쭉날쭉하다.** `미래를 보는 창 - 전자신문` 은 14자에 의미도 흐리다
- 줄이려면 `' - '` 로 잘라 뒤쪽을 쓰는 식의 규칙이 필요한데, 원본이 주는 문자열이라
  규칙이 언제 깨질지 모른다. **추측으로 자르지 않는 편이 낫다**

### C. 번호를 버리고 이름만 — `[zdnet.co.kr]`

- 가장 짧다
- 같은 출처가 두 번 인용되면 구분이 안 되고, "위에서 [2] 말한" 식으로 가리킬 수 없다

**A 를 권한다.** 번호는 유지하고 도메인을 붙인다.

## 폭이 걱정되면 — 설정 항목

한 문단에 인용이 셋이면 `[1 zdnet.co.kr]` × 3 = 약 45자가 는다.
본문 폭이 96ch 인 기본값에서는 견딜 만하지만, 취향이 갈릴 수 있다.

```
citations   number  →  [1]                 (지금)
            domain  →  [1 zdnet.co.kr]     (기본값 제안)
            off     →  마커를 지우고 아무것도 안 남긴다
```

`GT_SCHEMA` 에 `citations`(enum, def `domain`)를 넣으면 된다.
사전 키는 `opt.citations.*` 규칙을 그대로 따른다.

## 구현 지점

전부 `markdown.js` 의 `mark()` 안이다.

```js
const host = url ? new URL(url).hostname.replace(/^www\./, '') : '';
const text = mode === 'domain' && host ? `[${n} ${host}]` : `[${n}]`;
```

- `new URL()` 이 던질 수 있다 — `try/catch` 로 감싸고 실패하면 번호만
- 주소를 모르면(스트리밍 중) 지금처럼 번호만. 스트림이 끝나면 도메인이 붙는다
- 링크·호버·`http(s)` 검사는 지금 그대로

## 회귀 방지

- 도메인이 붙고 `www.` 가 떨어지는가
- 이상한 URL 에서 던지지 않고 번호만 남는가
- `off` 면 번호도 안 남는가
- 링크 주소·target·rel 은 그대로인가

# 2. ↑↓ 로 이전·다음 프롬프트

> **구현 완료 (2026-09-16 · 0.3.0).** 아래 설계 그대로 갔다.
> 구현하면서 하나가 더 나왔다 — 낙관적 렌더의 임시 id 가 `local-${Date.now()}` 라
> 같은 밀리초에 두 번 보내면 id 가 겹쳐 앞의 줄을 덮어썼다. 회귀 검사가 잡았다.
> 카운터를 붙여 유일하게 만들었다(`local-<ms>-<n>`).

## 지금 상태

- 입력줄은 **`textarea`** 다. `Shift+Enter` 로 여러 줄을 쓴다
- 후보 목록(`setSuggest`)은 **수동 표시**다. 선택 상태가 없고 `Tab` 이 완성한다
  → **↑↓ 와 충돌하지 않는다**
- 팔레트(`⌘K`)와 사이드바 검색은 이미 ↑↓ 를 쓰지만 **각자 포커스를 가져간다**
  → 입력줄 핸들러와 겹치지 않는다

## 기록을 어디서 가져오나

**`store.state.messages` 에서 `role === 'user'` 를 순서대로 뽑는다.**

- 새 상태를 만들지 않는다
- **새로고침해도 남는다** — 대화를 다시 읽으면 그대로 복원된다
- 원본 UI 에서 보낸 것도 들어온다. 우리가 보낸 것만 기억하는 것보다 자연스럽다
- **대화를 옮기면 그 대화의 기록으로 바뀐다.** 셸 기록(전역)과는 다르지만,
  "이 대화에서 내가 뭐라고 물었지" 가 실제로 원하는 것이라고 본다

대안(별도 배열)은 새로고침에 날아가고 원본에서 보낸 것을 놓친다. 쓰지 않는다.

## 움직임

`idx` 하나로 다룬다. `null` 이면 '지금 쓰던 것'.

```
초기      idx = null,  draft = ''

↑        idx === null  →  draft 저장, idx = 마지막
         그 외          →  idx = max(0, idx - 1)

↓        idx === null  →  아무 일 없음
         마지막이면     →  idx = null, draft 복원
         그 외          →  idx = idx + 1

Enter    보내고 나면 idx = null, draft = ''
Esc      idx = null, draft 복원 (후보 목록이 떠 있으면 그게 먼저다)
```

**기록을 오가면 입력줄 전체가 바뀐다.** 기록 안에서 고친 내용은 다음 이동 때 버린다 —
bash 처럼 항목별 편집분을 들고 있지 않는다. 단순함을 택한다.
처음 ↑ 를 누르기 직전의 **초안은 지킨다.** 그게 없으면 쓰던 걸 날린다.

## 여러 줄일 때가 핵심이다

`textarea` 라 ↑↓ 는 원래 **커서를 움직이는 키**다. 그걸 뺏으면 여러 줄 편집이 깨진다.

```
↑ 로 기록을 넘긴다   ← 커서가 첫 줄에 있을 때만
↓ 로 기록을 넘긴다   ← 커서가 마지막 줄에 있을 때만
그 외                ← 기본 동작(커서 이동)을 그대로 둔다
```

```js
const v = input.value, at = input.selectionStart;
const collapsed = input.selectionStart === input.selectionEnd;   // 선택 중이면 기본 동작
const onFirstLine = !v.slice(0, at).includes('\n');
const onLastLine = !v.slice(at).includes('\n');
```

한 줄짜리 입력에서는 둘 다 참이라 늘 기록으로 간다 — 셸과 같은 감각이다.

## 걸리는 것들

- **IME** — 입력줄 핸들러 맨 앞의 `composing(e)` 가드를 그대로 지나간다.
  조합 중 ↑↓ 는 후보 선택에 쓰이므로 절대 가로채면 안 된다
  ([2026-09-02 IME 건](../issue/2026-09-02-ime-enter-eats-last-char.md))
- **기록이 비었을 때** — 아무 일도 하지 않는다. `preventDefault` 도 하지 않는다
- **대화 전환** — 기록의 출처가 store 라 자동으로 바뀐다. `idx` 는 `null` 로 되돌린다
- **아주 긴 프롬프트** — 그대로 넣는다. 자동 높이(`autosize`)가 이미 240px 에서 멈춘다
- **후보 목록** — ↑↓ 로 기록을 넘긴 뒤에는 `refreshSuggest()` 를 다시 불러야
  `:` 로 시작하는 기록에 맞는 후보가 뜬다

## 어디에 둘까

`index.js` 의 입력줄 `keydown` 안, `Tab` 분기 앞뒤. 상태(`idx`·`draft`)는
그 클로저의 지역 변수로 둔다. store 에 넣을 이유가 없다 — 화면 하나의 편집 상태다.

기록을 뽑는 함수만 순수하게 뺀다.

```js
// store.js
userHistory() { return state.messages.filter((m) => m.role === 'user').map((m) => m.text); }
```

## 회귀 방지

- ↑ 가 마지막 프롬프트를, 한 번 더 누르면 그 앞의 것을 넣는가
- 맨 앞에서 ↑ 를 더 눌러도 넘어가지 않는가
- ↓ 로 되돌아와 초안이 복원되는가
- **여러 줄에서 커서가 첫 줄이 아니면 기록으로 가지 않는가** (그 반대도)
- 선택 영역이 있으면 기본 동작인가
- 조합 중(IME)에는 손대지 않는가
- 보내고 나면 위치가 초기화되는가
- 기록이 비었을 때 아무 일도 없는가
