# 시트 스킨 — 스프레드시트로 보이는 대화

> **구현됨 (0.8.0, 2026-09-24)** — `src/content/skins/sheet.js`. 구조는 [스킨 구조 설계](2026-09-24-skin-architecture.md) 를 따른다.
> 이 문서와 달라진 점: `GT.tty` 를 갈아끼우지 않고 스킨 레지스트리에 등록한다(§5). 표는 칸을 ` | ` 로 이은 고정폭 한 행으로
> 그린다(§8 의 미정을 가장 단순하게 풀었다). 이미지는 셀 안의 자리표시 행이다. 제품 이름은 쓰지 않는다 — 제목은 `<대화 제목>.xlsx`.

터미널 말고 **두 번째 껍데기**를 만든다. 화면이 Excel 처럼 보인다.

목업: [`docs/mockup/sheet-skin.html`](../mockup/sheet-skin.html) (브라우저로 열면 그대로 보인다)

## 1. 이건 테마가 아니다

지금 `theme` 은 **CSS 변수 한 벌**이다.

```js
'modern-dark': { '--gt-bg-1': '#0d1117', '--gt-fg': '#c9d1d9', … }
```

색만 바뀐다. 구조는 `tty.js` 가 한 벌로 못 박고 있다 — 상단바 · 스크롤백 · 입력줄.
**Excel 은 구조가 다르다.** 행 번호, 열 머리글, 수식 입력줄, 시트 탭.

그래서 한 단계 위의 개념이 필요하다.

```
skin      terminal | sheet        ← 새로 만든다. 골격이 갈린다
 └ theme  modern-dark | crt-green | amber | (시트용 팔레트)
```

`skin` 이 DOM 골격과 CSS 를 고르고, `theme` 은 그 안의 색을 고른다.

## 2. 무엇을 무엇에 대응시키나

| Excel | 우리 | 진짜 동작하나 |
|---|---|---|
| 제목 표시줄 `…xlsx — Excel` | 파일명처럼 꾸민 대화 제목 | 꾸밈 |
| 리본 탭 (파일·홈·삽입…) | — | **꾸밈** |
| 리본 버튼 (붙여넣기·글꼴…) | — | **꾸밈** |
| 이름 상자 `B14` | 지금 커서가 있는 셀 | 동작 |
| **수식 입력줄 `fx`** | **프롬프트 입력** | **동작** |
| 행 번호 1,2,3… | 줄 번호 | 동작 |
| A 열 | 누가 말했나 (`나` / `GPT`) | 동작 |
| **B 열** | **대화 본문** | **동작** |
| C 열 | 시각 | 동작 |
| **시트 탭** | **대화 목록** | **동작** |

Excel 흉내를 내려고 실제 Excel 기능을 구현할 이유가 없다.

## 3. 한 행에 한 줄 — 이게 핵심 결정이다

두 가지 방식이 있었다.

### A. 한 행에 메시지 하나

```
1  나    docker 사이트 알려줘.
2  GPT   여기! - Docker 공식 사이트: docker.com - Docker Hub: …  (셀 하나에 전부)
```

- 긴 응답이 셀 하나에 들어가 **행 높이가 화면을 넘긴다**
- 줄 바꿈을 켜도 Excel 스럽지 않다. 시트에 그런 셀은 잘 없다

### B. 한 행에 한 줄 ← **이걸 쓴다**

```
1  나    docker 사이트 알려줘.
2  GPT   여기!
3        · Docker 공식 사이트: docker.com
4        · Docker Hub: hub.docker.com
6  나    compose 파일 예시도 줘.
```

- **행 번호가 자연스럽게 는다.** 시트를 쓰는 사람의 눈에 익은 모양이다
- 문단·목록 항목·코드 한 줄이 각각 한 행
- A 열은 **그 메시지의 첫 줄에만** 찍는다. 이어지는 줄은 비운다 — 실제 시트에서
  머리 항목만 적는 습관과 같다
- 코드블록은 고정폭 글꼴 + 연한 배경으로 여러 행에 걸친다

렌더 구조가 터미널과 다르다. 터미널은 `markdown.render()` 가 블록 노드를 만들지만,
시트는 **줄 단위로 쪼개야** 한다. 그래서 `markdown.js` 에 줄 단위 출력이 하나 더 필요하다
(기존 렌더를 건드리지 않고 별도 함수로).

## 4. 무엇이 어려운가 — 정직하게

### (1) 줄 나누기가 새 코드다

`markdown.render()` 는 `<p>`, `<ul>`, `<pre>` 같은 **블록**을 만든다.
시트는 **줄의 배열**이 필요하다.

```js
// 새로 만들어야 하는 것
GT.markdown.lines(text, opts)
// → [{kind:'text'|'code'|'item', text, indent}, …]
```

인라인 처리(굵게·링크·인용 번호)는 기존 `inline()` 을 그대로 쓴다.
**표는 어떻게 할지 아직 못 정했다** — 시트 안의 표라 오히려 자연스러울 수 있고,
셀 병합처럼 보이게 할 수도 있다. `[미정]`

### (2) 스트리밍 중 행이 계속 늘어난다

답이 흘러오면 줄이 하나씩 생긴다. 지금 `renderplan` 은 **메시지 단위**로 재조정하는데,
시트는 **행 단위**여야 한다. 그렇지 않으면 한 글자마다 표 전체를 다시 그린다.

→ `renderplan` 의 서명을 행 단위로 만들거나, 스트리밍 중인 메시지만
마지막 몇 행을 다시 그리는 식으로 좁힌다. **설계에서 제일 조심할 곳이다.**

### (3) 입력이 두 군데로 보인다

Excel 은 수식 입력줄과 셀이 같은 내용을 보여준다. 우리도 그렇게 하면 그럴듯한데,
입력 상태를 두 곳에 그리면 커서·IME 처리가 꼬인다.

→ **수식 입력줄 하나만 진짜 입력**으로 하고, 셀에는 같은 글자를 비추기만 한다.
셀은 `readonly` 도 아닌 그냥 `<td>` 다.

### (4) 기존 기능을 얼마나 옮기나

명령(`:help`, `:ls`…), 팔레트, 사이드바, ↑↓ 기록 — 전부 터미널 전제로 만들어졌다.

**1차에서는 이렇게 가른다.**

| 그대로 쓴다 | 시트용으로 바꾼다 | 1차에서 뺀다 |
|---|---|---|
| store · conversation · tap · markdown(인라인) | tty 골격 · theme CSS | 팔레트(`⌘K`) |
| commands 실행 · compose · convops | 사이드바 → **시트 탭** | `:messup` 등 진단 |
| ↑↓ 기록 · IME 처리 | 상태줄 → 상태 표시줄 | 스캔라인·커서 설정 |

명령은 수식 입력줄에 `:help` 처럼 그대로 친다. Excel 에서 `=` 로 수식을 시작하듯
`:` 로 명령을 시작하는 셈이라 어색하지 않다.

## 5. 어떻게 나눌까 — 파일 구조

```
src/content/
  tty.js          지금 것. 터미널 골격            ← 손대지 않는다
  sheet.js        새로. 시트 골격                 ← 새 파일
  skin.js         새로. 둘 중 하나를 고른다        ← 작은 분기
  theme.js        CSS 두 벌을 들고 있게 된다
```

`index.js` 는 `GT.tty.*` 를 직접 부른다(40곳 남짓). 전부 고치면 위험하다.

→ **`GT.skin` 이 같은 인터페이스를 내주고, 안에서 tty 또는 sheet 로 넘긴다.**
`GT.tty` 라는 이름을 유지한 채 구현만 갈아끼우는 방법도 있다. 후자가 변경이 적다.

```js
GT.tty = GT.config.get('skin') === 'sheet' ? GT.sheet : GT.terminal;
```

필요한 인터페이스: `mount · render · renderChrome · system · setMode · setSuggest ·
focus · visible · toggle · applyConfig · ui`. **시트도 이 목록을 다 채워야 한다.**

## 6. 단계

### 1단계 — 보이기만 한다
설정 `skin: sheet` 로 바꾸면 시트 골격이 뜨고, 대화를 읽어 행으로 그린다.
입력은 수식 입력줄에서 되고, 전송·스트리밍이 동작한다.

### 2단계 — 시트답게
시트 탭으로 대화 전환, 셀 선택(↑↓←→ 로 행 이동), 상태 표시줄 채우기.

### 3단계 — 곁가지
`Ctrl+\`` 로 터미널 ↔ 시트 전환, 확대/축소, 표 렌더 확정.

## 7. 회귀 방지

- 터미널 스킨이 **하나도 안 바뀌는가** (기존 테스트 1121건이 그대로 통과해야 한다)
- 스킨을 바꿔도 store 가 그대로인가 (대화 내용은 껍데기와 무관하다)
- 스트리밍 중 표 전체를 다시 그리지 않는가
- 한 메시지가 여러 행이어도 A 열이 첫 줄에만 찍히는가
- 코드블록의 들여쓰기가 살아 있는가
- 명령(`:help`)이 수식 입력줄에서 동작하는가
- IME 조합 중 Enter 가 전송되지 않는가 (터미널과 같은 가드)

## 8. 정하지 못한 것

- **표를 어떻게 그리나** — 시트 안의 표라 자연스러울 수도, 병합 셀로 보일 수도
- **이미지를 어떻게 넣나** — Excel 은 셀 위에 떠 있는 개체다. 행 높이를 키워
  셀 안에 넣을지, 떠 있게 할지
- **리본을 얼마나 그리나** — 지금 목업은 6개 그룹뿐이다. 더 그리면 그럴듯하지만
  세로 공간을 먹는다. 접는 기능(실제 Excel 에도 있다)을 붙일 수도
- **어느 Excel 을 흉내내나** — 목업은 Microsoft 365 의 초록 리본이다.
  더 옛날 것(2010 의 파란 리본)이 눈에 덜 띌 수도 있다

### 성능 — 150턴(1390행) 대화에 40문단 답 스트리밍

```
                         처음      메시지 캐시   + 그리드 행   + flex-basis 0
한 델타 중앙값           21.9ms    ~20ms        11.7ms        1.8ms
한 델타 p95              29ms      ~28ms        18ms          2.2ms
첫 렌더                  70ms      -            50ms          45ms
같은 조건 terminal       1.3ms
```

단계별 측정: 스크롤 읽기/쓰기를 막으면 렌더 13.3ms → 1.2ms. 칸 글자 변경 뒤 레이아웃 0ms, 행 끼우기 뒤 11.6ms.
터미널 CSS 를 절 단위로 빼 가며 찾으니 `.gt-root` 세로 flex 안의 격자가 `flex: 1 1 auto` 라 행 하나마다
격자 내용 전체 높이를 다시 쟀다. `flex: 1 1 0` 으로 0.2ms.
