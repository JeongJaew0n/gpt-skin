# 답변 중에는 메시지 보내기를 막는다

작성 · 구현: 2026-10-12 · 0.30.0

## 1. 지금 무슨 일이 일어나나

답을 만드는 동안 입력줄에 글을 쓰고 Enter 를 치면 (`shell/prompt.js` 의 Enter 처리):

```
입력줄을 비운다 → 명령이 아니면 GT.compose.send(text)
  → 원본 입력창에 글을 넣는다 (tryInject)
  → 보내기 버튼을 찾는다 — 답변 중에는 원본이 보내기 버튼 대신 중지 버튼을 띄운다 → 못 찾음
  → 원본 입력창에 Enter 키 이벤트를 쏜다
  → { ok: true } 를 돌려준다 → 우리 화면에 '내가 보낸 글' 을 먼저 올린다 (낙관적 렌더)
  → 2초 뒤 원본 입력창에 글이 남아 있으면 '안 보내졌다' 경고 (watchSent)
```

| 무엇 | 상태 |
|---|---|
| 답변 중에는 보내기 버튼이 없고 중지 버튼이 있다 | `[확정 — 코드가 이 전제를 쓴다]` 생각 중 표시 · esc 중단이 '중지 버튼이 있는가' 를 정본으로 쓴다 |
| 원본이 답변 중의 Enter 를 무시한다 | `[가정]` — 확인: 답변 중에 원본 입력창에서 직접 Enter 를 쳐 본다 |
| 그 결과 우리 화면에 보내지 않은 글이 '보낸 글' 로 올라가고, 원본 입력창에는 글이 남는다 | `[가정]` 위 가정이 맞으면 그렇다. 남은 글은 답이 끝난 뒤 다음 보내기 때 앞에 붙거나 원본 화면에서 의도치 않게 보내질 수 있다 |

즉 지금은 '막는' 장치가 없고, 원본이 무시하는 것에 기대고 있다. 그 사이 우리 화면이 사실과 다른 것(보낸 적 없는 글)을 보여 줄 수 있다.

## 2. 무엇을 만드나

**답변 중에는 메시지 보내기만 막는다.** 입력과 명령은 막지 않는다.

| | 답변 중 동작 | 이유 |
|---|---|---|
| 글자 입력 | 그대로 된다 | 다음에 보낼 글을 미리 써 두는 것은 막을 이유가 없다 |
| Enter (메시지) | **보내지 않는다.** 입력줄의 글을 그대로 두고 한 줄로 알린다 | 원본이 받지 않는 요청을 넣지 않는다 · 쓴 글을 잃지 않는다 |
| Enter (`:` 명령) | 그대로 실행 | 명령은 원본에 보내지 않는 우리 일이다 (`:clear` · `:bug` · `:skin` …) |
| esc · Ctrl+C | 그대로 중단 | 막는 동안 빠져나갈 길이 있어야 한다 — 알림 문구에 함께 적는다 |
| 답이 끝남 | 자동으로 보내지 않는다. 입력줄 글은 남아 있고 Enter 로 보낸다 | 자동 전송은 사용자가 확인하지 않은 순간에 보내는 것이다. 원하면 따로 정한다(§6) |

### 화면 표시

- 답변 중에는 입력줄 자리표시 문구를 바꾼다: '답변 중 — 끝나면 보낼 수 있습니다 · esc 중단'
  (터미널 `gt-input` · 시트 수식 입력줄 · none 명령줄 모두. 문구는 i18n ko · en)
- 막힌 Enter 를 치면 한 줄 알림(`system('info', …, { quiet: false })`). 같은 답 동안 여러 번 쳐도 한 번만 남긴다 — 스크롤백이 같은 줄로 덮이지 않게
- 터미널 상태줄 모드(`STREAM`)는 지금도 뜬다. 바꾸지 않는다

## 3. '답변 중' 판정

정본은 **원본의 중지 버튼이 있는가**(`GT.compose.stopButton()`)다 — 생각 중 표시와 esc 중단이 이미 같은 기준을 쓴다.
우리 스트림 상태(`GT.store.streamingId`)는 보조로만 쓴다.

```
answering = !!GT.compose.stopButton() || !!GT.store.state.streamingId
```

- 중지 버튼만으로 보면: 우리가 스트림 시작을 놓쳐도 막는다
- 스트림 상태만으로 보면: 원본은 끝났는데 우리 end 를 놓치면 영영 막힌다 → 그래서 둘의 OR 를 쓰되,
  **스트림 상태가 N초(예: 120초) 넘게 갱신되지 않고 중지 버튼도 없으면 막지 않는다** — 영구 잠금 방지
- 그림 생성 중(`GT.store.isDrawing()`)도 원본은 중지 버튼을 띄운다 `[가정]` — 중지 버튼 기준이면 따로 볼 필요가 없다

`GT.compose.send` 자체에서도 막을지: **막지 않는다.** 보내기 경로는 입력줄 하나뿐이고(팔레트는 명령만 채운다), 두 곳에서 막으면 문구가 두 번 뜬다.

## 5. 확인 계획

- 회귀 검사 (vm 샌드박스, 고친 코드를 깨뜨려 실패 확인)
  - 답변 중 Enter: `compose.send` 를 부르지 않는다 · 입력줄 글이 그대로 · 알림 한 줄
  - 같은 답 동안 두 번 쳐도 알림은 한 줄
  - 답변 중 `:help` 는 실행된다
  - 답변 중이 아니면 예전처럼 보낸다
  - 스트림 상태만 남고 중지 버튼이 없는 채 오래되면 막지 않는다
  - 자리표시 문구가 답변 시작 · 끝에 바뀐다 (터미널 · 시트 · none)
- 실측 `[미정]` — 사용자 승인 후, 새 대화에서
  1. 답변 중 원본 입력창에서 직접 Enter → 원본이 무시하는지 · 줄을 세우는지 (§1 의 가정)
  2. 고친 판에서 답변 중 Enter → 막히고 글이 남는지, 끝난 뒤 Enter 로 보내지는지

## 6. 정하지 않고 남긴 것 (사용자 결정이 필요)

- **끝나면 자동으로 보내기**(대기열): 편하지만 확인하지 않은 순간에 보내진다. 원본이 줄 세우기를 지원하는지(§5-1)에 따라 다시 본다. 이번 범위 밖
- 막는 대신 **'중단하고 보내기'** 한 번에 하기(Shift+Enter 같은 키): 이번 범위 밖
- 알림 대신 입력줄을 흔들거나 색을 바꾸는 표시 — 디자인 결정. 이번에는 한 줄 알림 + 자리표시 문구만
