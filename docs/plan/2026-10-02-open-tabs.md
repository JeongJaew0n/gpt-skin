## 구조

- `src/content/tabs.js` — `GT.tabs`. `[{ id, href, title, seen }]`
  - `open(path, title)` 대화를 열면 끝에 넣는다(있으면 본 시각만). 새 대화 화면(`/`)은 넣지 않는다
  - `title(id, text)` 제목은 대화 원본을 읽은 뒤에 들어온다
  - `close(id)` 오른쪽(없으면 왼쪽) 탭을 돌려준다 — 지금 탭을 닫으면 거기로 간다. 남은 탭이 없으면 새 대화
  - `step(dir)` / `go(dir)` 끝에서 넘어가면 반대쪽 끝. 지금 대화가 탭에 없으면(새 대화 화면) 첫 · 끝 탭
  - 최대 20개. 넘치면 가장 오래 안 본 탭부터 닫는다
  - 프로젝트 안의 대화(`/g/<프로젝트>/c/<id>`)도 — id 는 `/c/` 뒤, href 는 주소 그대로
- `index.js` — 부팅 때 저장된 탭을 읽고 지금 대화를 넣는다. 600ms 라우팅 감시에서 주소가 바뀌면 `open`. 제목이 들어오면 `title`.
  탭이 바뀌면 상단(탭 줄)을 다시 그린다
- 터미널(위쪽) · 시트(아래쪽) 탭 줄이 같은 목록을 그린다 — 스킨을 바꿔도 탭이 그대로다. `:chats` 는 탭 줄을 보이거나 숨긴다(기본 숨김 —
  숨기면 지금 대화 탭만)
- `Ctrl+,` / `Ctrl+.` — 물리 키(`Comma` · `Period`)로, 조합 가드 앞에서 본다(한글 상태). `⌘,` 는 브라우저 설정 키라 건드리지 않는다.
  스킨이 꺼져 있으면 원본에 맡긴다

## 저장 위치

`local` 을 쓴다. `sync` 는 대화 id 와 제목이 구글 계정 동기화로 올라간다.

## 0.25.1 — 단축키를 연달아 누르면 스킨이 벗겨진다

사용자 보고. 원인 `[확정 — 코드]`: `navigate.to` 의 안전장치(0.24.1)가 1.2초 뒤 "주소가 목적지와 다르면" 페이지를 새로 열었다.
`Ctrl+.` 로 A → B 를 빠르게 넘기면 A 의 확인이 "주소가 A 가 아니다(이미 B)" 로 읽혀 **A 로 페이지를 통째로 새로 열었다** —
그동안 원본 화면이 드러나고, 스킨을 기본으로 켜 두지 않았으면 원본으로 남는다.

고친 것: 새로 여는 것은 **마지막 이동이고, 주소가 떠나기 전 그대로일 때만**(= 라우터가 되돌렸을 때만).
- 그 뒤에 다른 이동이 있었으면 앞선 확인은 아무것도 안 한다 — 왕복(A → B → A)도 막는다
- 다른 곳으로라도 움직였으면 라우터가 살아 있는 것이라 새로 열지 않는다

실제 페이지에서 이 경로를 탔는지는 `:bug` 의 `navigate-fallback` 기록으로 확인할 수 있다 `[미정 — 사용자 보고서 미확인]`.

## 0.25.2 — 빠르게 넘기면 탭 이름이 섞인다

사용자 보고: 탭 1 · 2 · 3 을 1 → 2 → 3 으로 빠르게 넘기면 2 · 3번 탭 이름이 1번으로 바뀐다.

원인 `[확정 — 코드]`: 주소는 즉시 바뀌고 화면 대화는 대화 원본(API)이 도착한 뒤에 바뀐다. store 변경 처리기가 그 사이
'지금 주소의 id + 지금 화면의 제목(아직 1번)' 을 짝지어 저장했다. 같은 뿌리로, 늦게 도착한 응답이 그때의 주소를 달고
화면에 들어가 **다른 대화 내용이 지금 주소로 깔릴 수** 있었다.

결정(사용자): 빠른 입력을 막지 않는다 — 막아도 느린 네트워크에서는 천천히 눌러도 재현된다. 대신 경쟁 상태를 고친다.

- **늦은 응답은 화면에 넣지 않는다** — `pull` 이 받는 사이 주소의 대화가 바뀌었으면 버린다
- **store 에 화면 대화의 id(`conversationId`)** — API 로 받아 넣을 때만 세운다. 탭 제목은 주소의 id 와 이 id 가 같을 때만 store 에서 쓴다
- **탭 제목의 1차 출처는 API 응답** — id 로 짝지어져 있어 늦게 와도 섞이지 않는다(화면에는 안 넣어도 제목은 채운다)
- **단축키 이동은 debounce 0.25초** — 강조는 누르자마자 옮기고, 실제 이동은 손을 멈춘 뒤 한 번만. 1 → 2 → 3 이면 2번은 불러오지도 않는다
- **받는 중 표시** — 막지 않고 표시만: 터미널은 지금 탭에 `⠴`, 시트는 탭 이름 뒤에 `…`
- 같이: `conversation.idFromPath` 가 `/c/` 로 시작하는 주소만 알아봐 **프로젝트 안의 대화(`/g/…/c/<id>`)는 대화 원본을 아예 안 읽었다** —
  같은 꼴을 알아보게 했다(원본 사이드바의 프로젝트 링크 8개가 이 꼴 — 실측)

이미 틀어진 제목은 그 탭을 한 번 열면 API 제목으로 덮인다. 실제 ChatGPT 에서는 아직 확인 전 `[미정]`.

## 0.26.0 — 대화를 받는 동안 로딩바 · 본문 흐림

사용자 결정: 탭 구석의 표시(⠴ · …)만으로는 '아직 이전 대화' 라는 걸 놓친다 — 본문에는 대화 원본이 도착할 때까지 이전 대화가 남아 있다.

- 본문(터미널) · 격자(시트) 위에 2px 막대. 흐르는 막대(진행률을 모른다), 움직임 줄이기면 멈춘 막대
- 받는 동안 본문을 흐리게(불투명도 0.5) — 새 대화로 착각하지 않게
- **300ms 넘게 걸릴 때만** 띄우고, 띄웠으면 **최소 300ms** 유지 — 빠른 로딩에서 번쩍이지 않게. 대기는 받기 시작한 순간부터 센다
  (처음 짠 것은 단축키를 누를 때마다 다시 세서 계속 누르는 동안 막대가 안 떴다 — 검사가 잡았다)
- 판단은 `GT.tabs` 한 곳(`barShown()`), 스킨은 그리기만 한다
- 같이: 시트에서 탭 줄을 숨긴 상태(기본)면 지금 탭에 받는 중 표시(`…`)가 안 붙던 것

하네스(헤드리스 크롬): 두 스킨 모두 받기 시작 0.1초엔 막대 없음 · 0.5초엔 막대(2px) · 본문 불투명도 0.5 · 끝나면 사라짐.
실제 대화 원본이 얼마나 걸리는지는 재지 않았다 `[미정]` — 대부분 300ms 안이면 막대는 드물게만 보인다.
