# 코드 리뷰 지적 수정 — 0.26.1 ~ 0.26.7

작성 · 구현: 2026-10-02 · 0.26.0 전체 코드 리뷰에서 나온 것 중 **재현으로 확인한 것만** 고친다.

## 0. 재검사 (오판 여부)

리뷰는 코드를 읽고 추론한 것이었다. 고치기 전에 각 지적을 vm 샌드박스에서 실제 모듈을 돌려 다시 확인했다
(스크립트는 세션 임시 폴더. 아래 출력은 그대로 옮긴 것).

| # | 지적 | 재현 결과 | 판정 |
|---|---|---|---|
| 1 | 브라우저 탭 두 개가 열린 탭 목록을 서로 덮어쓴다 | 두 인스턴스가 같은 저장소 사용: `B 가 z 를 연 뒤 x,y,z` → `A 가 w 를 연 뒤 x,y,w` (z 사라짐) | `[확정]` |

| 4 | 대화 조작 API 가 `success:false` 여도 성공이라고 알린다 | `:rename` → `이름 변경: 새 이름` + 상단바 제목까지 바뀜 · `:pin` → `고정: …` | `[확정]` |
| 5 | 입력줄에서 글을 고르고 Ctrl+C 하면 복사 대신 생성 중단 | `선택 영역이 있는 Ctrl+C → defaultPrevented = true · stop 호출 = 1` | `[확정]` |

오판으로 판명된 것: 사이드바 메뉴 '삭제' 두 단계 — 헤드리스 크롬에서 같은 리스너 구조를 재현하니 정상(`armed=1 menuConnected=true`).

이번에 **고치지 않는 것**
- 수확(`store.applyHarvest`)이 짧은 fiber 글로 본문을 덮을 여지 `[가정]` — 실제로 일어나는지 모른다. `:bug` 의 `truncated` 기록으로 먼저 빈도를 본다
- 사이드바 목록의 프로젝트 대화 `href` 가 `/c/<id>` 인 것 — 원본이 이 주소를 프로젝트 주소로 넘겨 주는지 실측하지 않았다 `[미정]` (확인: 로그인 ChatGPT 에서 `/c/<프로젝트 대화 id>` 로 이동해 주소가 어떻게 되는지)
- 프로젝트 주소에 프로젝트 이름이 들어가는지 `[가정]` — 확인하지 않았지만 마스킹은 어차피 경로 모양만 남기는 게 규칙이라 고친다
- `tap.js` 의 닿지 않는 분기 — 동작 차이 없음. MAIN world 파일을 정리 목적으로 건드리지 않는다

## 1. 열린 탭 — 브라우저 탭끼리 맞춘다 (0.26.1)

- `tabs.js` 가 `chrome.storage.onChanged`(local, `gt.openTabs`)를 듣고 메모리의 목록을 새 값으로 바꾼다.
  내용이 같으면(자기 저장의 메아리) 다시 그리지 않는다.
- 남는 경쟁: 두 탭이 같은 순간(같은 이벤트 루프 틱 안)에 저장하면 여전히 나중 것이 이긴다 `[가정: 드묾]`.
  사람이 두 창에서 동시에 대화를 여는 경우라 받아들인다.

## 2. 프로젝트 대화 경로 (0.26.2)

- `commands.js` `:archive` · `:rm` — `location.pathname === '/c/' + id` → `GT.conversation.idFromPath() === id`
- `commands.js` `:share` — 지금 대화가 그 대화면 이동하지 않는다. 다른 대화면 그 대화의 `href`(없으면 `/c/<id>`)로
- `sidebar.js` `currentId()` → `GT.conversation.idFromPath()`
- `navigate.js` 버그 기록 → `GT.bugs.maskPath(href)`

## 3. 로딩 표시 — 마지막 이동만 끈다 (0.26.3)

- `GT.tabs.loading(true)` 가 번호를 돌려준다. `loading(false, 번호)` 는 그 번호가 마지막일 때만 끈다.
  번호 없이 부르면 예전처럼 끈다.
- `index.js` 라우팅 감시가 번호를 들고 pull 이 끝나면 넘긴다.

## 4. 대화 조작 결과를 그대로 알린다 (0.26.4)

- `:rename` · `:pin` · `:archive` · `:rm` · 사이드바 메뉴(고정 · 보관 · 삭제) · 다중 보관이 `success` 가 거짓이면 실패로 알린다.
  `:rename` 은 실패하면 상단바 제목 · 문서 제목도 바꾸지 않는다.
- 새 문구는 i18n 사전(`cmd.op.rejected`)에서 꺼낸다. ko · en.

## 5. 지우거나 보관한 대화는 열린 탭에서도 닫는다 (0.26.5)

- 성공했을 때만 `GT.tabs.close(id)`. 지금 대화면 원래대로 새 대화로 간다.

## 6. Ctrl+C — 고른 글이 있으면 복사 (0.26.6)

- 입력줄에 선택 영역이 있으면 Ctrl+C 를 건드리지 않는다(브라우저 복사). 없을 때만 생성 중단.
  Windows Terminal 과 같은 규칙이다. 맥의 ⌘C 는 원래 건드리지 않았다.

## 7. 여러 줄 글의 '안 보내짐' 감지 (0.26.7)

- contenteditable 은 공백 · 줄바꿈을 빼고 비교한다(넣을 때 `injectInto` 가 쓰는 `squash` 와 같은 기준). textarea 는 그대로.
