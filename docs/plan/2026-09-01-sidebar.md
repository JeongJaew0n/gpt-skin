# 좌측 사이드바 (대화 목록 상시 표시)

- 상태: **구현됨** (2026-09-01) — 브라우저 확인 대기
- 관련 아트보드: 04 `Chats.dc.html` (전체화면 `ls` 뷰). **사이드바는 목업에 없다.**

## 배경

지금 터미널에는 상시 표시되는 좌측 메뉴가 없다. 대화 목록은 `ls` 명령으로
스크롤백에 표 형태로 찍히는 게 전부고, `:open <n>` 으로 연다.
원본 ChatGPT 에는 항상 보이는 사이드바가 있으니 그 자리가 비어 보인다.

## 먼저 측정한 것 — 이게 계획의 전제다

데이터 출처가 될 원본 DOM 을 확인했다. **현재 방식은 신뢰할 수 없다.**

`GT.compose.conversations()` 는 `a[href^="/c/"]` 를 긁는다. 그런데 2026-09-01 측정:

| 창 너비 | `nav` 개수 | 대화 링크 | 사이드바 토글 버튼 |
|---|---|---|---|
| 넓을 때 (~1568px) | 2 | 있음 (`history-item-0..27`) | 있음 |
| 좁을 때 (~1038px) | **0** | **0** | **없음** |

좁은 창에서는 원본이 사이드바를 **DOM 에서 통째로 내린다.** 펼칠 버튼조차 없다.
즉 지금 `ls` 가 "사이드바에서 대화를 찾지 못했다"고 답하는 건 버그가 아니라
**데이터 출처가 사라진 상태**다.

`[확정]` 좁은 창에서 원본 사이드바는 DOM 에 없다.
`[확정]` 원본 사이드바가 있을 때는 대화 링크 · 프로젝트 링크(`/g/g-p-*`)가 모두 DOM 에 있다.
`[미정]` 넓은 창에서 목록이 몇 개까지 렌더되는지 (관측된 `history-item-*` 는 28개까지).

## 무엇을 만드나

tmux 식 좌측 분할 페인. 전체화면 `ls` 뷰는 그대로 둔다 — 역할이 다르다.

- **사이드바** = 빠른 전환. 항상 보임, 좁음.
- **`ls` 뷰** = 자세히 보기. 미리보기 패널 · 정렬 · 태그 (04 아트보드).

```

│ ❯ 일본어…    │ ─────────────────────────────────────────│
│   k8s-hpa    │  ❯ 질문                                  │
│              │  ⏺ gpt-5 …                               │
│ ~/projects   │                                          │
│   컨설턴트/  │                                          │
│   세무사/    │                                          │

│   상담 비교  │                                          │

├──────────────┴──────────────────────────────────────────┤
│ ❯ 입력                                                   │
├──────────────────────────────────────────────────────────┤

```

원본의 `고정됨 / 프로젝트 / 채팅` 을 경로 은유로 옮긴다 —
`~/pinned`, `~/projects/<name>/`, `~/chats`. `ls ~/chats` 명령과 어휘가 맞아떨어진다.

## 데이터 출처 — 여기가 핵심 결정

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A** | 원본 DOM 스크래핑 (현행) | 추가 작업 없음 | **좁은 창·접힘에서 빈다.** 렌더된 개수까지만 |
| **B** | 원본 사이드바를 강제로 마운트 | DOM 그대로 쓸 수 있음 | 원본 레이아웃을 조작해야 함. 깨지기 쉬움 |
| **C** | 백엔드 API 직접 호출 | 창 크기·접힘과 무관. 전체 목록 · 페이지네이션 | 경로 확인 필요. 스키마 변경에 노출 |
| **D** | 본 것을 캐시 (`chrome.storage.local`) | 출처가 비는 순간을 메움 | 낡은 목록을 보여줄 수 있음 |

**채택: C 를 주 경로, A 를 폴백, D 를 항상 켬.**

### 0단계 결과 — 스키마 확정 (2026-09-01 실측)

쿠키만으로는 안 되고 **Bearer 토큰이 필요하다.** 토큰은 `/api/auth/session` 의 `accessToken`.
sentinel proof-of-work 는 **필요 없다** — 그건 전송 경로에만 붙는다.

```
GET /api/auth/session
  → { user, expires, account, accessToken, authProvider, sessionToken, ... }

GET /backend-api/conversations?offset=0&limit=N&order=updated
  Authorization: Bearer <accessToken>
  → { items: [{
        id, title, create_time, update_time,
        pinned_time,          // null 이 아니면 고정됨
        gizmo_id,             // null 이 아니면 프로젝트 소속
        is_archived, is_starred, is_temporary_chat,
        workspace_id, snippet, ...
      }],
      total, limit, offset }

GET /backend-api/gizmos/snorlax/sidebar
  Authorization: Bearer <accessToken>
  → { items: [{ gizmo: { id, display: { name }, ... }, tools, files, ... }],
      cursor }
```

확인된 것:

- `[확정]` 대화 목록은 **offset/limit 페이지네이션**이고 `total` 을 준다.
- `[확정]` 프로젝트 목록은 **cursor** 방식이며, 이름은 `gizmo.display.name`.
- `[확정]` 대화 항목의 `gizmo_id` 가 프로젝트 `gizmo.id` 와 맞물린다 →
  **대화 한 번, 프로젝트 한 번, 총 2회 호출로 전체 그룹핑이 된다.**
- `[확정]` 인증 없이 호출하면 `conversations` 는 200 이지만 `items` 가 비고,
  `snorlax/sidebar` 는 401 이다. 조용히 비는 쪽이 더 위험하다 — 빈 목록을 성공으로 오해하지 말 것.
- `[확정]` 읽기 GET 에 sentinel 불필요.

### 토큰 취급 규칙

`accessToken` 은 민감값이다. 구현에서 지킨 것:

- **메모리에만** 둔다 (5분 TTL). `chrome.storage` 에 절대 쓰지 않는다.
- 로그로 찍지 않는다.
- `chatgpt.com` 이외의 어디로도 보내지 않는다.
- 401 이 오면 캐시를 버리고 다음 호출에서 다시 받는다.

## 내비게이션

`:open` 은 지금 `location.href = ...` 로 **전체 페이지 로드**를 한다. 이건 바꿔야 한다.

- 전체 로드는 확장을 재부팅시키고, 앞서 확인한 **부분 렌더 문제**(콜드 로드에서 턴 누락)를 정통으로 밟는다.
- SPA 이동이 낫다. 조사 중에 이 방법이 동작하는 걸 확인했다:

```js
history.pushState({}, '', href);
window.dispatchEvent(new PopStateEvent('popstate'));
```

원본 `<a>` 가 DOM 에 있으면 그걸 클릭하는 게 더 안전하고, 없으면 위 방법을 쓴다.
어느 쪽이든 이동 후 `harvest` 는 이미 경로 변화 감시로 자동으로 돈다.

## 4차 — 고르면 비켜난다 (2026-09-01)

원본은 대화를 고르면 목록이 닫힌다. 오버레이라 본문을 가리고 있기 때문이다. 같게 맞췄다.

**설정을 끄지 않는다.** `sidebar.visible` 을 false 로 바꿔버리면 다음에 열 때도 안 나온다.
세션 한정으로 물러나는 `dismissed` 를 따로 뒀다 — 설정은 그대로다.

```
dismiss()   이번만 물러난다. config 안 건드림
toggle()    ≡ · ^B · :sidebar. dismissed 를 풀고 config 를 갱신
```

`sidebar.closeOnOpen`(기본 켬)으로 끌 수 있다. `:open <n>` 명령도 같은 동작이다.

### 토글 기준을 DOM 에서 표시 조건으로

`toggle()` 이 `isOpen()`(DOM 부착 여부)으로 뒤집고 있었다.
비켜난 상태에서 ≡ 를 누르면 열려야 하는데, DOM 에 기대면 마운트 타이밍에 흔들린다.
`shouldShow()`(config + dismissed + forcedOpen + 폭)로 바꿨다 — 의도가 진실이다.
테스트가 이걸 잡았다.

## 5차 — 보이지 않는 ⋯ 가 클릭을 먹고 있었다

"대화를 골라도 목록이 안 닫힌다"를 조사하다 찾았다.

`.gt-sb-dots`(행의 `⋯`)에 `opacity: 0` 만 줬다. **투명해도 자리는 차지하고 클릭은 받는다.**

```
행 영역     0 ~ 216px
숨은 ⋯     193 ~ 204px      ← 여기를 누르면 대화가 아니라 메뉴가 열린다
```

행 오른쪽 끝을 누르면 대화가 안 열리고 컨텍스트 메뉴가 뜬다. 목록도 그대로 남는다.
증상만 보면 "닫히는 기능이 고장난 것"과 구분이 안 된다.

```css
.gt-sb-dots { opacity: 0; pointer-events: none; }
.gt-sb-row:hover .gt-sb-dots { opacity: 1; pointer-events: auto; }
```

### 조사 과정에서 배운 것

- 브라우저 자동화의 좌표는 **스크린샷 좌표계**고 `getBoundingClientRect()` 는 **CSS 픽셀**이다.
  둘을 섞어 클릭하면 엉뚱한 곳을 누른다. 한동안 "이벤트가 아예 안 온다"에 속았다.
- `dismiss` 자체는 정상이었다. 실제와 같은 이벤트 순서
  (`pointerdown → mousedown → pointerup → mouseup → click`)를 가장 깊은 요소에 쏘면 잘 닫힌다.

### 재현이 안 될 때를 위해

`:health` 가 사이드바 상태를 한 줄로 찍는다.

```
사이드바: 표시=true 붙음=true 비켜남=false 직접켬=true 열면닫기=true 선택모드=false 행=40
```

## 6차 — 요구사항을 잘못 읽었다

4차에서 "대화를 고르면 목록이 비켜난다"를 만들었는데, 요청은 그게 아니었다.

```
내가 만든 것   목록에서 항목을 고르면 닫힌다
요청한 것      본문(메인 대화 영역)을 누르면 닫힌다   ← 오버레이 바깥 클릭
```

오버레이의 기본 동작이다. 바깥을 누르면 비켜나야 한다.

```js
const INSIDE_OVERLAY = '.gt-sidebar, .gt-burger, .gt-ctx, .gt-palette, .gt-scrim';
root.addEventListener('mousedown', (e) => {
  if (!GT.sidebar.isOpen()) return;
  if (hit(e).closest(INSIDE_OVERLAY)) return;   // 목록·손잡이·메뉴·팔레트는 '바깥'이 아니다
  GT.sidebar.dismiss();
});
```

`Escape` 로도 닫힌다. 단 팔레트가 열려 있으면 그쪽 몫이다.

4차의 '고르면 닫힘'은 그대로 둔다 — 원본도 그렇게 동작하고 서로 충돌하지 않는다.

## 7차 — 프로젝트 지연 로드와 폭 드래그 (2026-09-02)

**프로젝트 지연 로드.** 예전에는 첫 페이지(40개)에 걸린 대화만 프로젝트로 묶였다.
거기 안 걸린 프로젝트는 목록에 아예 없었다.

이제 `snorlax/sidebar` 가 주는 프로젝트를 **전부 헤더로 보여주고**,
처음 펼칠 때 `GET /backend-api/gizmos/<id>/conversations` 로 그 안을 읽어온다.
읽는 동안 하단에 `프로젝트 읽는 중…` 이 뜬다.

**폭 드래그.** 오른쪽 가장자리를 끌면 폭이 바뀌고 더블클릭하면 기본값으로 돌아온다.

설정은 `ch` 단위인데 드래그는 px 이라 환산이 필요하다.
`font-size × 0.6` 같은 어림값을 쓰지 않고 **실제 글자 폭을 재서** 나눈다 —
폰트를 바꾸면 어림값이 어긋난다. 끌리는 동안은 인라인 CSS 변수로 즉시 반영하고,
놓을 때 설정에 ch 로 저장하며 인라인 값을 걷어낸다(설정값이 다시 이기도록).

## 위험

- **원본 스키마 변경.** C 를 쓰면 응답 스키마에 의존한다. `onBreak` 정책 아래 두고,
  깨지면 A 로 자동 폴백하되 `soft()` 로 알린다.
- **매니페스트에 파일 추가 = ↻ 필요.** 새 파일 두 개가 들어가므로
  `stale-manifest-silent-death` 를 또 밟는다. preflight 목록 갱신을 3번 단계에 못 박아뒀다.
- **개인 정보.** 대화 제목은 캐시(D)에 남는다. `chrome.storage.local` 을 쓰고(sync 아님),
  `:sidebar clear-cache` 를 제공한다.
- **폭 경쟁.** 사이드바가 본문의 `wrap.columns` 를 먹는다. 좁은 창에서 본문이 뭉개지지 않게
  `sidebar.minColumns` 로 자동 숨김.
