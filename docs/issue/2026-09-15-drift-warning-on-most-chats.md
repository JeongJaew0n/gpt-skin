# 드리프트 경고가 거의 모든 대화에서 뜬다

```
[warn] 스트림 본문과 원본이 N% 다릅니다
```

한 대화의 문제가 아니라 **대부분의 대화에서** 뜬다.

실측: 2026-09-15 · `/c/6aa8c892-…` (면접 전날 식사 추천) + 최근 대화 18건 표본

**결론부터. 거의 전부 오탐이다.** 본문 내용은 같고, 마커 주변 문자 **1~3자**만 어긋난다.
그런데 임계가 비율이라 **응답이 짧으면 그 몇 자가 8% 를 넘는다.**

[2026-09-08 건](2026-09-08-drift-warning-false-positive.md)에서 마커를 걷어내고 비교하도록
고쳤는데, 그때 걷어낸 것은 `cite` 하나였다. **봉투는 다섯 종류였다.**

---

## 1. 실제로 얼마나 다른가

문제의 대화에서 API 원문과 fiber 원문을 둘 다 떠서 `stripMarks` 를 적용했다.

```
API 원문      730자  →  마커 제거  463자
fiber 원문    652자  →  마커 제거  466자
                              차이 3자 = 1%
```

**1% 다.** 임계 8% 아래다 — 이 완성 상태로는 경고가 안 뜬다.
그런데도 스트리밍 직후에는 떴다. 아래 3절이 그 이유다.

### 3자의 정체

두 가지가 겹쳤다.

**(가) 원본이 콜론을 하나 더 남긴다**

```
스트림  …있어.\n\n image_group{"layout":"carousel",…} \n\n내 픽은…
fiber   …있어.\n\n\n ::contentReference[oaicite:4]{index=4} \n\n\n내 픽은…
                     ^^
```

`::contentReference` — **콜론이 둘이다.** 우리 `OAI_MARK` 는
`:contentReference\[oaicite:(\d+)\]\{index=(\d+)\}` 만 지우므로 **앞의 `:` 가 남는다.**

**(나) 마커 주변 개행 개수가 다르다**

원본은 마커를 치환하면서 앞뒤 개행을 다르게 넣는다. 위 예에서 `\n\n` 대 `\n\n\n`.

공백까지 정규화(`\s+` → `' '`)해 다시 재 봤다.

```
공백 정규화 후   446자 대 448자   차이 2자 = 0%
```

**남는 2자가 (가)의 `: ` 다.** 즉 차이는 전부 마커 주변 잔재다. 본문 내용은 같다.

## 2. 봉투가 다섯 종류다

최근 대화 18건의 **응답 478개**를 훑었다.

| | |
|---|---|
| 마커가 있는 응답 | **53개** |
| 관측된 봉투 종류 | `cite` · `entity` · `image_group` · `memcite` · `genui` |

`cite` 만 인용이 아니다. 특히 **`memcite` 가 매우 흔하다** — 저장된 메모리를 참조할 때마다
붙는 것으로 보이며, 표본의 한 대화("일본어 번역 검토")에서는 거의 모든 응답에 하나씩 있었다.

```
699자 마커1 [memcite]
 44자 마커1 [memcite]      ← 짧다
781자 마커1 [memcite]
719자 마커1 [memcite]
…
```

`genui` 가 붙은 응답 중에는 **본문이 0자**인 것도 있었다.

### refs 대응은 정상이다 `[확정]`

봉투가 6개인데 `content_references` 는 7개라 인덱스가 밀리나 싶어 확인했다.

| 본문 봉투 | `refs[n].type` |
|---|---|
| `entity` | `entity` |
| `cite` | `grouped_webpages` |
| `entity` | `entity` |
| `cite` | `grouped_webpages` |
| `image_group` | `image_group` |
| `memcite` | `hidden` |
| — | `sources_footnote` ← 본문에 봉투 없음 |

**순서대로 1:1 로 맞는다.** 남는 `sources_footnote` 는 뒤에 붙는 것이라 `ctx.seen` 을
밀지 않는다. 인용 번호가 엉뚱한 출처를 가리키는 문제는 **없다.**

## 3. 왜 짧은 응답에서 반드시 터지나 — 구조적 결함

`health.js:104`

```js
const pct = Math.round((Math.abs(a.length - b.length) / Math.max(b.length, 1)) * 100);
const limit = Number(GT.config.get('drift.threshold')) || 8;
if (pct < limit) return;
```

**분자는 마커 개수에 비례하는 고정량(1~3자)이고, 분모는 응답 길이다.**

같은 3자 차이가 길이에 따라 이렇게 변한다.

| 응답 길이 | 비율 | 8% 임계 |
|---|---|---|
| 466자 | 1% | 통과 |
| 44자 | 7% | 아슬아슬 |
| **30자** | **10%** | **경고** |
| **20자** | **15%** | **경고** |
| 0자 (`genui` 만 있는 응답) | — | **즉시 경고** |

**짧게 답할수록 경고가 뜬다.** 내용은 멀쩡한데.

표본에 44자·0자짜리가 실제로 있었으므로 이것이 "대부분의 대화에서 뜬다" 의 주된 이유다.

## 4. 남은 가능성 — verify 타이밍 `[미정]`

문제의 대화는 완성 상태에서 1% 였다. **그런데 사용자는 그 대화에서 경고를 봤다.**
그러므로 `verify` 가 돌던 시점의 fiber 는 지금과 달랐다는 뜻이다.

`index.js:175` 가 스트림 종료 400ms 뒤에 fiber 를 읽는다. 그때 원본이 아직 최종 렌더를
끝내지 않았으면 fiber 가 짧다. `VERIFY_MIN_RATIO = 0.5` 가 절반 미만만 걸러내므로,
**60~90% 쯤 그려진 상태는 통과해 버린다** — 그러면 큰 차이로 경고가 뜨고, 더 나쁘게는
`rec.text = fiber` 로 **화면이 덜 그려진 텍스트로 교체된다.**

[2026-09-09 건](2026-09-09-url-marker-dropped.md) §2 의 "마지막 글자 잘림" 이 같은 뿌리로 보인다.
그때도 `[가정]` 으로 남겼다.

**확인 방법**: 검색이 걸리는 질문을 보내고 `:log on` 상태로 스트림 종료 직후
fiber 길이와 최종 길이를 비교한다. 아직 하지 않았다.

## 5. 고칠 방향 (아직 적용하지 않았다)

### (1) 비교 전에 공백을 정규화한다

목적은 **내용이 같은지 보는 것**이지 공백 개수를 세는 것이 아니다.

```js
const norm = (t) => strip(t).replace(/\s+/g, ' ').trim();
```

이 대화에서 3자 → 2자로 줄었다.

### (2) 마커가 남기는 구두점을 같이 걷어낸다

`::contentReference` 의 앞 콜론. `OAI_MARK` 앞에 `:?` 를 붙이면 된다.

```js
/:?:contentReference\[oaicite:(\d+)\]\{index=(\d+)\}/
```

**실측으로 확인한 모양만 반영한다.** (1)+(2) 로 이 대화는 0자 차이가 된다.

### (3) 절대량 하한을 둔다 ← 이것이 핵심

비율만으로는 짧은 응답을 다룰 수 없다. **차이가 몇 자 안 되면 경고하지 않는다.**

```js
const diff = Math.abs(a.length - b.length);
if (diff < DRIFT_MIN_CHARS) return;      // 예: 20자
if (pct < limit) return;
```

(1)·(2)로 잔재를 지워도 원본이 마커 처리를 바꾸면 또 몇 자가 어긋난다.
**하한이 있으면 그때마다 사용자를 귀찮게 하지 않는다.** 정말 본문이 날아간 경우는
수십~수백 자가 어긋나므로 여전히 잡힌다.

### (4) verify 를 더 기다린다 (4절 확정 후)

`VERIFY_MIN_RATIO` 를 올리거나, fiber 길이가 안정될 때까지 한 번 더 본다.
**4절을 확인하기 전에는 건드리지 않는다.**

---

## 회귀 방지

- 다섯 봉투(`cite`·`entity`·`image_group`·`memcite`·`genui`)를 모두 걷어내는가
- `::contentReference` 의 앞 콜론이 남지 않는가
- 공백만 다른 두 텍스트를 같다고 보는가
- **짧은 응답(30자)에서 3자 차이로 경고가 뜨지 않는가**
- 본문이 실제로 날아간 경우(절반 이하)는 여전히 잡는가
