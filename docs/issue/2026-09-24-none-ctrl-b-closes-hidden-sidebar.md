# none 스킨에서 Ctrl+B 가 먹지 않는다 · 전환하면 명령줄이 열려 있다

**상태: 해결 (0.6.1 · 0.6.2)** · 보고 2026-09-24 (사용자, 0.6.0 확인 중) · 재현 2026-09-24

사용자가 0.6.0 의 none 스킨을 확인하며 셋을 보고했다.

1. `:skin none` 을 치면 "터미널 흔적이 남는다 (Ctrl+; 한 것처럼 됨)"
2. 명령줄이 열려 있을 때 `Ctrl+;` 를 누르면 닫히면 좋겠다 (요청)
3. `Ctrl+B` 가 안 먹힌다. "아예 창에서 포커스 아웃돼 버린다"

---

## 1. 전환하면 명령줄이 열린 채로 뜬다 `[확정]`

터미널을 켠 상태에서 `:skin none` + Enter. 화면 하단에 명령줄과 결과 패널이 떠 있었다.

```
[info]  노 스킨 (명령만) 스킨으로 바꿨습니다
❯ :help 로 명령 목록 · esc 로 닫기
```

**원인** — `GT.skin.switch()` 가 전환 전의 보임 상태(`wasVisible`)를 새 스킨에 그대로 넘겼다.
터미널이 보이던 중이었으니 none 도 '보임' 으로 시작했고, none 에서 '보임' 은 명령줄이 열린 상태다.
사용자는 이걸 "터미널이 남았다 / Ctrl+; 를 누른 것 같다" 로 읽었다.

**수정** — 원본을 가리지 않는 스킨(`covers: false`)으로 바꿀 때는 닫힌 채 시작한다.
가리는 스킨으로 바꿀 때는 예전처럼 보임 상태를 유지한다.

결과 문구의 "노 스킨 (명령만) 스킨으로" 처럼 '스킨' 이 겹치던 것도 같이 고쳤다
(`스킨을 바꿨습니다: 노 스킨 (명령만)`).

## 2. Ctrl+; 는 열기만 했다

요청대로 여닫기 토글로 바꿨다. 열려 있으면 닫는다.

## 3. Ctrl+B 가 첫 번째에 아무 일도 안 한다 `[확정]`

명령줄이 열리고 포커스가 명령줄(`.gn-input`)에 있는 상태에서 실제 `Ctrl+B`.

```
keydown  key=b  code=KeyB  ctrl=true  target=gn-input  defaultPrevented=true
→ window blur 없음 · document.hasFocus()=true · 포커스는 그대로 gn-input
→ shadow root 안에 .gt-sidebar 없음 (루트의 자식: gn-dock 하나)
```

키는 우리 전역 핸들러가 받았고 `GT.sidebar.toggle()` 까지 갔다. 그런데 목록이 붙지 않았다.

**원인** — `toggle()` 은 "지금 보여야 하는가" 를 `shouldShow()` 로 판단해 뒤집는다.
`shouldShow()` 는 터미널의 규칙이다 — `sidebar.visible` 이 켜져 있고 창이 넓으면 참.
none 은 그 규칙을 따르지 않고 **직접 열었을 때만** 띄운다(`forcedOpen`).
그래서 none 에서 목록이 안 보이는데도 `shouldShow()` 는 참이었고, 첫 `Ctrl+B` 는 '닫기' 가 됐다.

**부작용** — 그 '닫기' 가 `sidebar.visible = false` 로 **저장됐다.** 터미널로 돌아가면 목록이 꺼져 있다.
재현하며 이 설정을 끄게 되어, 재현 직후 `:set sidebar.visible true` 로 되돌렸다.

**수정**
- "보여야 하는가" 를 스킨이 답한다 — 계약에 `sidebarShown()` 추가.
  terminal 은 예전대로 `shouldShow()`, none 은 `forcedOpen && !dismissed`.
- 여닫기를 `sidebar.visible` 에 저장할지를 스킨이 정한다 — 계약에 `persistSidebar` 추가.
  none 은 저장하지 않는다. 원본에 목록이 있어 잠깐 여는 것이고, 터미널의 설정을 건드리면 안 된다.
- none 은 저장값·창 폭과 무관하게, 직접 열면 열린다.

### "창에서 포커스 아웃" — 원인은 포커스가 BODY 로 빠지는 것 `[확정]` (0.6.2)

0.6.1 을 올린 뒤 브라우저에서 다시 쟀다 (2026-09-24, 0.6.1 · build 22:48 확인).

| 순서 | 동작 | 결과 |
|---|---|---|
| 1 | 터미널에서 `:skin none` | 스킨 `gt-root gn-root`, 닫힘, 원본 깨끗. **포커스 = BODY** |
| 2 | `Ctrl+;` | 열림, 포커스 = 명령줄 |
| 2 | `Ctrl+;` 한 번 더 | 닫힘. **포커스 = BODY** |
| 3 | 명령줄 열고 `Ctrl+B` | 목록이 원본 왼쪽 위에 뜬다. 한 번 더 누르면 닫힌다 |
| 4 | 명령줄 닫고 컴포저에 `abc` 입력 후 `Ctrl+B` | 우리가 건드리지 않음(`defaultPrevented=false`). 커서 3 → 2 (macOS 기본 동작). 포커스 = 컴포저 그대로, blur 없음 |

닫힌 상태의 `Ctrl+B` 는 원본으로 간다. 원본 컴포저에서 이 키는 커서를 한 칸 뒤로 옮기는 키라 가로채지 않는다 —
대화 목록은 명령줄을 연 상태에서 연다.

"포커스가 빠진다" 는 1·2 의 **BODY** 다. 스킨을 해체하거나 숨기면 포커스를 쥐고 있던 우리 입력줄이 사라져
포커스가 문서 본문으로 떨어진다. 그 뒤로는 무엇을 쳐도 어디에도 들어가지 않는다.

**수정 (0.6.2)** — 숨기기 전에 포커스가 우리 호스트 안에 있었으면 원본 컴포저로 돌려준다.
전환(`switch`)은 해체 **전에** 포커스 위치를 재 둔다 — 해체 뒤에 재면 이미 BODY 다.
포커스가 원래 원본에 있었으면 건드리지 않는다. 가리는 스킨(터미널)으로 바꿀 때도 원본에 주지 않는다.

**아직 브라우저로 안 본 것** `[미정]` — 0.6.2 를 다시 로드한 뒤 1·2 에서 포커스가 `prompt-textarea` 인지.
