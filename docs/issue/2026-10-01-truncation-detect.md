# 가끔 글자가 끊긴다 — `:bug` 에 안 남는다

테스터 보고: 가끔 답의 글자가 끊기는데, `:bug` 보고서에는 아무것도 안 남는다.

조사 · 수정: 2026-10-01 · 0.20.0

---

## 1. 무엇이 있었나 `[확정 — 코드]`

끊김의 신호를 코드가 이미 알고 있는 곳이 셋 있었다. 하지만 로그(`GT.log`)로만 흘려보내거나 경고 문구만 남겼다.
`:bug` 보고서에는 로그 줄을 넣지 않으므로(제목 등이 섞일 수 있다) 보고서에 아무것도 안 남았다.

| 신호 | 어디 | 예전 | 뜻 |
|---|---|---|---|
| 본문 델타를 버렸다 | `index.js` `end` | 로그만 | 화면에서 글자가 빠진 직접 신호 |
| 원본 화면(fiber)이 받은 본문보다 짧다 | `index.js` `verify` | 로그만 | 원본이 그리다 만 상태. 우리 화면은 받은 본문을 지킨다 (2026-09-18) |
| 받은 본문과 원본이 크게 다르다 | `health.js` `reconcile` | 경고 문구 | 드리프트 |

그리고 **아무 신호 없이** 끊기는 경우가 있다 — 우리 화면엔 짧게 그려졌는데 어느 경로도 이상을 모른다.
[2026-09-09](2026-09-09-url-marker-dropped.md) 의 "스트림이 중간에 멈추는 쪽" 이 원인 미확정으로 남아 있다.

## 2. 고친 것

### 있던 신호를 보고서에 남긴다

`deltas-dropped` · `original-partial` · `drift` 로 기록한다. 개수와 글자 수만 넣는다.

### 신호 없는 끊김 — 대화 원본(API)과 길이를 잰다

- 답이 끝나면(`end`) **8초 뒤** 대화 원본 API(`/backend-api/conversation/<id>`, 대화를 열 때 이미 쓰는 것)를
  한 번 읽어 **같은 메시지 id** 의 길이를 우리 화면과 잰다
- 8초인 까닭: `verify` 가 원본 화면이 더 길면 받아 교정하는데, 400ms 뒤 시작해 최대 세 번 더 본다(약 5.8초).
  그 전에 재면 교정 전 길이로 헛경보를 낸다
- 인용 마커와 공백을 걷어내고, 원본이 **20자 이상** 길 때만 `truncated` 로 기록한다(드리프트와 같은 하한 —
  마커 표기 차이는 실측 1~3자)
- 기록: 화면 길이 · 원본 길이 · 차이 · 버린 델타 수 · verify 재시도 수. 본문은 넣지 않는다
- **화면은 고치지 않는다.** 먼저 얼마나 자주 생기는지 본다 (사용자 결정 2026-10-01)
- 답마다 한 번. 대화를 옮겼거나 대화 id 가 없으면(비로그인 화면) 읽지 않는다. 확장이 교대하면 예약을 취소한다
- 본문을 하나도 못 받은 턴은 건너뛴다 — 그때는 이미 원본을 다시 읽는다

**비용: 답마다 GET 한 번.** (사용자 승인 2026-10-01)

## 3. 확인하지 않은 것 `[미정]`

- **로그인 화면에서 실제로 돌려 보지 않았다** — 테스트 브라우저에 계정이 없다. 메시지 id 가 스트림과 API 에서 같은지는
  `store.applyHarvest` 가 id 로 합치는 것을 근거로 같다고 본다 `[가정]`. 다르면 "원본에서 이 답을 찾지 못했다" 로그만 남고
  기록은 없다 — 테스터 보고서에 `truncated` 가 한 번도 안 나오면 이것부터 의심한다
- 보고서에 `truncated` 가 쌓이면 그때 화면 교정(원본으로 덮기)을 정한다

## 회귀 방지 — `test/bugs.test.mjs`

길이 비교(하한 · 공백 · 인용 마커 · 방향) · `checkTruncation` 을 `index.js` 에서 꺼내 실행(기록 · 한 번만 · 대화 옮김 · id 없음 ·
원본에 없음 · API 실패) · 검사 시점이 verify 창 뒤인가 · 교대 때 취소 · 세 신호 기록. 코드 8곳을 되돌려 실패를 확인했다.
