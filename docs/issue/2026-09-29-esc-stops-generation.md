# esc 로 후보·팔레트를 닫으면 답 생성도 멈춘다

**상태: 해결 (0.12.1)** · 발견 2026-09-28 (UX 조사 중 코드 대조) · 재현 2026-09-28 · 0.12.0 에서도 재현 2026-09-29

## 증상

생성 중에 자동완성 후보나 ⌘K 팔레트를 닫으려고 esc 를 한 번 누르면, 목록이 닫히면서 **답 생성도 멈춘다.**
되돌릴 수 없다. 사용자 입장에서는 "목록을 닫았더니 답이 끊겼다" 다.

## 원인 `[확정]`

전역 키 처리기는 창에 **캡처 단계**로 붙어 있다(`window.addEventListener('keydown', …, { capture: true })`).
그래서 입력줄 · 팔레트의 처리기보다 먼저 돈다.

- 전역 처리기 안의 `if (e.defaultPrevented) return` 은 "입력줄이 이미 처리한 esc" 를 거르려던 것이지만,
  입력줄 처리기는 아직 돌기 전이라 결코 참이 되지 않는다.
- 사이드바 분기는 `!GT.palette.isOpen()` 으로 팔레트를 비켰지만 생성 중단 분기는 비키지 않았다.

재현 (진짜 `prompt.js`, Node EventTarget, 브라우저의 전파 순서대로 window 캡처 → 입력줄):

```
생성 중 + 자동완성 후보가 떠 있음 + esc 한 번
수정 전  {"stop":1, "suggestClosed":1}
수정 후  {"stop":0, "suggestClosed":1}
```

## 수정

생성 중단 분기 앞에서 "닫을 층이 열려 있는가" 를 묻는다. 열려 있으면 그 층의 처리기가 닫게 두고 생성은 그대로 둔다.
층의 순서: 자동완성 후보 → 기록 초안 → 팔레트 → 사이드바(전역에서 먼저 닫음) → 비어 있는 none 명령줄 → 생성 중단.

none 의 동작이 바뀐다. 예전에는 생성 중에 빈 명령줄에서 esc 를 누르면 생성이 멈췄다. 이제는 명령줄이 먼저 닫힌다.
명령줄에 쓰던 글이 있으면 닫지 않으므로 그때는 생성이 멈춘다.

## 회귀 테스트

`test/esc.test.mjs` — 후보 · 기록 · 팔레트 · none 명령줄 각각에서 생성이 그대로인지, 열린 층이 없으면
esc 한 번에 멈추는지(예전 동작), 층 확인이 생성 중단보다 앞인지. 수정을 되돌리거나 층을 하나씩 빼면 해당 검사가 실패한다.
