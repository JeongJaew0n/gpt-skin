# 확장을 업데이트하면 열린 탭이 멈추고 '새로고침해주세요' 가 뜬다

애드가드 같은 확장은 새로고침 없이 멀쩡한데 gpt-skin 은 자주 먹통이 된다.

조사·수정: 2026-09-28 · 0.10.0

---

## 1. 원인 `[확정]`

크롬은 확장을 다시 로드(업데이트 · `chrome://extensions` 의 ↻ · `:reload`)하면
**이미 열려 있는 탭의 콘텐츠 스크립트를 확장에서 끊는다.** 그리고 새 코드를 넣어 주지 않는다 —
새로 여는 페이지에만 들어간다.

우리는 끊긴 것을 감지하면(`chrome.runtime.id` 가 사라짐, 4초 간격) 물러나고 안내를 띄웠다.

```
gpt-skin 확장이 다시 로드 됐습니다. 기능 사용을 위해서는 페이지를 새로고침해주세요
```

**재로드 뒤 다시 붙는 경로가 없었다.** `manifest` 권한은 `storage` 하나였고,
서비스워커에 `onInstalled` · `scripting.executeScript` 가 없었다.

개발 중이라 버전을 자주 올린 것이 이를 키웠다 — 9월 10일 이후 20번. 올릴 때마다 열린 탭이 전부 멈췄다.

### 애드가드는 왜 괜찮은가 `[가정]`

애드가드 소스는 보지 않았다. 일반적인 이유다.

- 광고 차단의 핵심이 `declarativeNetRequest` 규칙이라 **브라우저가 네트워크 단에서** 처리한다.
  확장이 재로드돼도 규칙은 계속 먹는다. 우리는 전부 페이지 안 스크립트다
- 웹스토어 확장은 크롬이 한가할 때 조용히 갈아끼운다
- 재로드 뒤 열린 탭에 스크립트를 다시 넣는다 — 이번에 우리도 이걸 했다

## 2. 고친 것

### 서비스워커가 다시 넣는다 (`service-worker.js`)

`onInstalled` 가 `install` · `update` 로 오면 열린 `chatgpt.com` 탭을 찾아 매니페스트의
콘텐츠 스크립트를 같은 순서로 `chrome.scripting.executeScript` 한다.

- 파일 목록은 **매니페스트에서 읽는다** — 두 곳에 적으면 갈린다
- isolated 를 먼저, MAIN(tap) 을 나중에
- 탭 하나가 실패해도 나머지는 계속한다. 버려진(discarded) 탭은 건드리지 않는다
- 권한 `scripting` 을 더했다. 심사 근거는 `docs/store/review-notes.md` 에 적었다

`:reload` 도 이제 **탭을 새로고침하지 않는다.** 재주입이 그 탭에 실패했을 때만 새로고침한다.

### 옛 것과 새 것의 교대 — 여기가 어려운 곳이었다

재주입하면 한 페이지에 옛 인스턴스(고아)와 새 인스턴스가 **함께** 산다. 코드로 확인한 함정 셋이다.

| 함정 | 무엇이 잘못되나 | 대응 |
|---|---|---|
| **MAIN world 의 옛 tap 이 안 죽는다** | MAIN world 는 확장과 무관하다. 그냥 넣으면 fetch 를 이중으로 감싸 **같은 스트림을 두 번 읽고**, harvest·verify 에 두 번 답한다 | tap 에 세대 번호(`window.__gptSkinTap.gen`, 열거 안 됨). 세대가 지난 tap 은 새 요청을 통과시키고 메시지에 답하지 않는다 |
| **옛 인스턴스가 새 화면을 지운다** | 옛 것이 4초 뒤 고아 감지로 물러나며 `GT.cover.remove()` 를 부르는데, 이게 **id 로** 호스트·페이지 스타일을 지운다. 그 사이 새 것이 붙었으면 새 화면이 날아간다 | 새 것이 뜨자마자 `gpt-skin:takeover` DOM 이벤트를 쏜다. 옛 것은 **새 것이 아무것도 그리기 전에** 동기로 물러난다. 늦게 물러날 때는 세대 표식을 보고 화면을 건드리지 않는다 |
| **옛 메시지 리스너가 영원히 산다** | `protocol.js` 의 `window.message` 리스너가 정리 목록에 없었다. 옛 것이 tap 메시지를 계속 받아 죽은 화면을 그리려 든다 | `GT.stop()` 으로 뗀다 |

같은 월드에 재주입되면 전역 `GT` 가 새 것으로 바뀐다. 그래서 옛 인스턴스는 부팅 때 잡아 둔
자기 모듈(`const MY = GT`)로 물러난다.

### 탭에서 켜 둔 상태를 이어받는다

`Ctrl+\`` 로 켠 상태는 탭 메모리에만 있다. 이어받지 않으면 업데이트 때마다 원본으로 돌아가
**여전히 먹통처럼 보인다.** 새 것은 교대 신호를 보내기 전에 켜짐 여부를 읽는다.
옛 것이 고아 감지로 **먼저** 물러나 이미 화면을 치운 경우를 위해, 물러날 때 `data-gpt-skin-was-on`
표식을 남기고 새 것이 읽고 지운다.

### '새로고침해주세요' 를 없앴다

할 일이 없으므로 띄우지 않는다. 예전 판이 남긴 안내가 떠 있으면 새 인스턴스가 걷는다.

## 3. 실제 크롬에서 확인했다

헤드리스 크롬 152 에 확장을 `Extensions.loadUnpacked`(CDP)로 올리고, ChatGPT 탭을 연 뒤
**같은 경로로 한 번 더 올려**(↻ 와 같다) 0.5초 간격으로 페이지 상태를 찍었다.

### 처음 시도 — 두 가지가 틀렸다

```
기준          tap 세대 2   isolated 세대 ie5w9   켜짐 false
    59ms      ...                                  켜짐 true   ← 탭에서 켠 것으로 만든다
   561ms      tap 세대 2   isolated 세대 uvylb   켜짐 false   was-on "1"
```

- isolated 는 재주입됐는데 **tap 은 안 들어왔다**
- **켜 둔 상태를 잃었다**

워커에서 `reinject()` 를 직접 불러 보니 **30,276ms** 가 걸렸다(결과는 성공).
`chrome.scripting.executeScript` 는 **주입한 파일의 마지막 식이 Promise 면 그것이 끝날 때까지
기다린다.** `index.js` 는 `(async function boot(){…})()` 로 끝나고, 부팅은 컴포저·스레드를 최대
수십 초 기다린다. 그동안 MAIN 주입이 줄 서서 멈췄다. `:reload` 의 3초 대기도 이 때문에 헛돌았을 것이다.

→ `index.js` 끝에 `void 0;` 을 두어 완료 값이 Promise 가 아니게 했다.
→ 교대 경로에서 남긴 was-on 표식이 찌꺼기로 남아(`"1"`), 고아 감지 경로에서만 남기게 했다.

### 고친 뒤

```
기준          tap 세대 2   isolated 50rlf   켜짐 false
    43ms                                    켜짐 true
   545ms      tap 세대 3   isolated 6y7mk   켜짐 false    ← 둘 다 재주입, 교대 완료
 30734ms      tap 세대 3   isolated 6y7mk   켜짐 true     ← 부팅이 끝나 이어받음

  PASS  페이지는 새로고침되지 않았다 (timeOrigin 같음)
  PASS  tap 재주입 (세대 +1)
  PASS  isolated 재주입 (세대 바뀜)
  PASS  호스트 하나
  PASS  켜 둔 상태를 이어받았다
  PASS  표식은 치워졌다
```

## 4. 첫 전환만은 새로고침이 필요하다 `[확정]`

재주입을 넣은 **첫 업데이트(0.9.1 이하 → 0.10.0 이상)에서는 효과가 없다.** 업데이트 순간 탭에서
돌고 있던 것은 옛 판이고, 옛 판은 교대를 모른다. 새 판이 옛 판을 고칠 수는 없다.

사용자가 0.11.0 으로 업데이트한 뒤 "여전히 새로고침해야 하고 안내도 뜬다" 고 보고해 재현했다.
같은 경로에 옛 판을 깔고 탭을 열어 켜 둔 뒤, 새 판 파일로 덮어 `loadUnpacked` 로 업데이트했다.

**0.9.1 → 0.11.0**

```
   411ms  새 코드 재주입됨 (tap 세대 1, 새 인스턴스)   화면 있음
  3237ms  옛 코드의 고아 감지(4초 간격)가 돔 — 호스트·스타일·클래스를 id 로 지우고
          '새로고침해주세요' 를 띄움
 30661ms  새 코드가 켜려 하지만 화면이 이미 지워져 아무것도 안 보임 → 새로고침해야 함
```

**0.10.0 → 0.11.0**

```
   413ms  새 코드 재주입 · 교대 (옛 0.10.0 은 교대 신호에 비켜 줌)   안내 없음 · 화면 유지
 30639ms  부팅이 끝나 켜 둔 상태로 다시 켜짐
```

즉 **0.10.0 이상이 탭에 올라간 뒤부터** 업데이트에 새로고침이 필요 없다. 옛 판이 떠 있는 탭은 한 번만
새로고침하면 된다.

옛 판 대비 방어(새 판이 호스트·클래스 id 를 바꿔 옛 코드의 삭제를 피하고, 안내를 CSS 로 가리는 것)는
넣지 않았다. 한 번만 생기는 전환이고, id 를 바꾸는 것은 되돌리기 어려운 변경이라 비용이 크다.

## 5. 남은 것

- **재주입 뒤 다시 켜지기까지의 공백** `[가정]` — 교대 순간 옛 화면은 치워지고, 새 화면은 부팅이
  끝나야 켜진다. 헤드리스(로그인 없음)에서 약 30초였다. 로그인한 탭은 컴포저·스레드가 이미 있어
  짧을 것으로 본다.

- **재로드 순간 흐르던 답** `[미정]` — 옛 tap 은 이미 읽던 스트림은 끝까지 읽어 보내도록 뒀다.
  새 isolated 가 그걸 받아 이어 그리는지는 확인하지 않았다. 못 받아도 부팅의 `pull('boot')` 가 대화를
  다시 읽는다.
- **같은 월드냐 새 월드냐** `[미정]` — 재주입된 isolated 스크립트가 옛 것과 같은 월드에서 도는지 확인하지
  않았다. 두 경우 모두 동작하도록 짰다(`const MY = GT`, 최상위 `const`/`let` 없음).

## 회귀 방지 — `test/reinject.test.mjs`

- tap 을 여러 번 넣어도 ping 에 한 번만 답한다 / **스트림 응답을 한 번만 갈라 읽는다**
- 열린 탭마다 isolated 먼저, MAIN 나중 · 파일은 매니페스트와 같다
- 실패한 탭을 건너뛰고 계속한다 · 버려진 탭은 건드리지 않는다
- `:reload` — 붙었으면 새로고침하지 않고, 실패했으면 새로고침한다
- `index.js` 의 완료 값이 Promise 가 아니다 (실제로 계산해 본다)
- 켜 둔 상태를 이어받는다 · 새로고침 안내를 띄우지 않는다

각 검사는 해당 코드를 되돌려 실패하는 것을 확인했다. 처음 쓴 fetch 검사는 **비스트림 주소로만** 시험해서
옛 래퍼를 되돌려도 통과했다 — 스트림 주소로 다시 써서 물게 했다.
