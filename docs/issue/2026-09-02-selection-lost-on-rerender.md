# 조금만 드래그해도 위쪽 영역이 통째로 선택된다

- 상태: 원인 특정 — **미수정**
- 관련 파일: `src/content/tty.js`, `src/content/index.js`

## 증상

스크롤백에서 텍스트를 조금 드래그하면 의도한 범위를 넘어 **위쪽 영역 전체가 선택된다.**

## 원인 — 스크롤백을 통째로 다시 그린다

`render()` 는 매번 스크롤백을 비우고 처음부터 다시 만든다.

```js
// src/content/tty.js:252
ui.scroll.textContent = '';
s.messages.forEach((m) => {
  ui.scroll.appendChild(m.role === 'user' ? turnUser(m) : turnAssistant(m));
});
```

그리고 이 `render()` 가 **1초마다 무조건** 불린다.

```js
// src/content/index.js:349
every(1000, () => { if (GT.tty.visible()) GT.tty.render(); });
```

바뀐 게 없어도 돈다. 이 틱의 목적은 시계와 경과 시간 갱신인데, 그걸 위해 본문 전체를 갈아엎는다.
(스트리밍 중에는 `store.onChange` 로도 매 델타마다 불린다 — 그건 필요한 갱신이다.)

## 실측 (2026-09-02)

메시지 58턴짜리 대화에서 측정했다.

### 선택이 살아남지 못한다

문단 하나의 텍스트 노드에 6글자 범위를 선택해두고 지켜봤다.

| 시점 | 선택 길이 | 선택한 노드가 살아있나 | 스크롤백 첫 자식이 그대로인가 |
|---|---|---|---|
| 직후 | **6** | ✓ | ✓ |
| 1.3초 후 | **0** | **✗ (분리됨)** | **✗ (다른 객체)** |
| 2.6초 후 | 0 | ✗ | ✗ |

선택을 걸어둔 텍스트 노드가 DOM 에서 **떨어져 나가고** 선택이 사라진다.

### 갈아엎는 규모

`MutationObserver` 로 4.8초 관측:

| 항목 | 값 |
|---|---|
| 스크롤백 직계 자식 | 59 |
| 전체 하위 노드 | **1,341** |
| 관측 중 추가된 노드 | 118 (= 59 × 2회) |
| 제거된 노드 | 118 |

**약 2.4초마다 59개 블록(하위 1,341노드)이 통째로 교체된다.**

## 왜 '위쪽 전체'가 선택되는가 `[가정]`

여기까지는 실측이고, 아래는 추론이다.

드래그 중에는 브라우저가 앵커(시작점)를 기준으로 선택을 늘린다.
그 도중 앵커 노드가 DOM 에서 제거되면 앵커가 무효가 되고,
브라우저는 컨테이너 기준으로 다시 잡는다 — 그 결과 **컨테이너 처음부터 커서까지**가 선택된다.
"조금 드래그했는데 위쪽 전체가 잡히는" 모양과 일치한다.

`[미검증]` 네이티브 드래그는 합성 이벤트로 재현되지 않아(선택 확장은 브라우저 내부 동작)
이 부분만 직접 확인하지 못했다. 다만 **앵커 노드가 드래그 도중 사라진다**는 사실은 위 표로 확인됐다.

## 곁가지 — 이미 깨져 있던 가정

`tty.js` 의 mouseup 핸들러는 "드래그로 텍스트를 골랐으면 포커스를 뺏지 않는다"를 위해
선택 길이를 확인한다.

```js
if (picked()) return;   // 선택이 있으면 입력창으로 포커스를 옮기지 않는다
```

그런데 선택이 1초 안에 지워지므로 **이 가드는 대부분 무의미하다.**
드래그를 마치고 잠깐 뒤 아무 데나 누르면 이미 선택이 없다.

## 고칠 방향

1. **바뀌지 않았으면 다시 그리지 않는다.**
   메시지 id + 본문 길이 + 스트리밍 여부로 서명을 만들어 이전과 같으면 건너뛴다.
   1초 틱의 목적인 시계·경과시간은 해당 노드만 직접 갱신한다.

2. **메시지 단위로 갱신한다.**
   전체를 비우는 대신 id 로 매칭해 바뀐 블록만 교체한다.
   스트리밍 중에는 마지막 블록 하나만 바뀐다.

3. **선택 중에는 손대지 않는다.**
   스크롤백 안에 선택이 있거나 마우스 버튼이 눌린 동안에는 재렌더를 미룬다.
   1·2번을 해도 스트리밍 중 갱신은 계속되므로 이 가드는 따로 필요하다.

셋 다 하는 게 맞다. 1·2번은 성능 문제이기도 하다 —
지금은 대화가 길어질수록 매초 수천 노드를 만들고 버린다.

## 재현 방법

```js
// 페이지 콘솔. 대화가 열린 상태에서.
const sh = document.getElementById('gpt-skin-host').shadowRoot;
const p = [...sh.querySelectorAll('.gt-p')].find(e => e.textContent.length > 40);
const tn = document.createTreeWalker(p, NodeFilter.SHOW_TEXT).nextNode();
const sel = sh.getSelection();
const r = document.createRange(); r.setStart(tn, 0); r.setEnd(tn, 6);
sel.removeAllRanges(); sel.addRange(r);
console.log('직후', String(sel).length, tn.isConnected);
setTimeout(() => console.log('1.3초 후', String(sel).length, tn.isConnected), 1300);
```
