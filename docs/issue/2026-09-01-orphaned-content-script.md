# 새로고침해도 안 고쳐지고, 제거 후 재설치해야만 오류가 사라진다

- 상태: **해결** (2026-09-01) — 우리 쪽 결함 2건 수정, 외부 요인 2건은 절차와 표식으로 대응
- 관련 파일: `src/content/index.js`, `src/content/tty.js`, `src/content/health.js`, `src/shared/defaults.js`

## 증상

- 소스를 고치고 페이지를 새로고침해도 예전 동작 그대로다
- 오류가 계속 떠 있다
- **확장을 제거했다가 다시 추가해야만** 오류가 사라진다

## 결론부터

**하나의 원인이 아니다. 네 가지가 겹쳐 있고, 그래서 "제거 후 재설치"만 듣는 것처럼 보였다.**
제거는 네 가지를 **전부** 리셋하는 유일한 조치이기 때문이다.

| 조치 | 확장 파일 캐시 | 고아 스크립트 | 오류 목록 | storage |
|---|---|---|---|---|
| 페이지 새로고침 | ✗ | 그 탭만 ✓ | ✗ | ✗ |
| `chrome://extensions` 의 **↻** | ✓ | **✗** | ✗ | ✗ |
| **제거 후 추가** | ✓ | ✓ | **✓** | **✓** |

↻ 만으로는 **열려 있는 탭의 고아 스크립트가 정리되지 않고**, 오류 목록도 그대로 남는다.
그 둘이 "아직 안 고쳐졌다"는 인상을 만든다.

---

## A. 크롬이 언팩 확장의 파일을 캐시한다 `[확정]`

페이지 새로고침은 확장 파일을 다시 읽지 않는다. 매니페스트뿐 아니라 **스크립트 내용도** 그렇다.

측정 방법 — `tap.js` 의 `harvest` 응답에 새 필드 `fiberEligible` 을 추가하고,
매니페스트는 건드리지 않은 채 페이지만 새로고침한 뒤 MAIN world 에 직접 물었다.

```js
window.postMessage({ __gpt_skin__: true, dir: 'i2m', kind: 'harvest' }, location.origin);
// → { total: 5, fiberHits: 3 }      ← fiberEligible 없음 = 옛 코드가 돌고 있다
```

디스크 파일에는 그 필드가 있었다. **↻ 없이는 새 코드가 안 올라온다.**

## B. 고아가 된 콘텐츠 스크립트가 계속 살아 돈다 `[확정]` — 우리 결함

↻ 를 누르면 이미 주입된 콘텐츠 스크립트는 **고아**가 된다.
`chrome.*` 는 죽지만 **JS 는 계속 돈다.** 우리가 등록해 둔 것 전부가 살아남았다.

| 등록물 | 위치 | 정리 코드 |
|---|---|---|
| `setInterval` 600ms (경로 감시) | `index.js` | 없음 |
| `setInterval` 1000ms (재렌더) | `index.js` | 없음 |
| `MutationObserver` (스레드 감시) | `index.js` | 없음 |
| `keydown` **capture: true** | `index.js` | 없음 |
| `resize` | `index.js` | 없음 |
| shadow root 터미널 + `html.gpt-skin-on` | `tty.js` | 없음 |

결과:

- **죽은 터미널이 화면을 계속 덮는다.** 원본 UI 는 `opacity:0` 인 채로 남아 조작이 안 된다.
- `keydown` 을 **캡처 단계에서** 가로채므로 `Ctrl+\``, `⌘K`, `/` 가 죽은 스크립트에게 먹힌다.
- 매 틱마다 무효화된 컨텍스트를 건드려 오류를 만든다.

이게 "새로고침으로 새로고침이 안 된다"는 체감의 정체다.
정확히는 **↻ 를 눌러도 그 탭은 그대로**이고, 탭을 새로고침해야 비로소 새 스크립트가 붙는다.

### 수정

등록하는 모든 것을 추적하고, 무효화를 감지하면 스스로 물러난다.

```js
const disposers = [];
const every  = (ms, fn)          => { const t = setInterval(fn, ms); disposers.push(() => clearInterval(t)); };
const listen = (t, ev, fn, o)    => { t.addEventListener(ev, fn, o); disposers.push(() => t.removeEventListener(ev, fn, o)); };
const observe = (obs, node, cfg) => { obs.observe(node, cfg); disposers.push(() => obs.disconnect()); };

every(4000, () => { if (!contextAlive()) shutdown('확장이 다시 로드됨'); });
```

`shutdown()` 은 disposer 를 모두 실행하고 `GT.tty.destroy()` 로 호스트·페이지 스타일·`gpt-skin-on` 클래스까지 걷어낸다.
**고아가 되면 화면에서 완전히 물러나 원본 UI 를 돌려준다.** `pagehide` 에서도 같은 정리를 한다.

## C. `chrome://extensions` 의 오류 목록은 영구적이다 — 우리가 부추겼다

그 목록은 **확장을 다시 로드해도 지워지지 않는다.** "모두 지우기"를 누르거나 확장을 제거해야 사라진다. `[확정]`

그런데 우리 `health.soft()` 는 경고마다 `console.warn` 을 찍었다.

```js
console.warn('[gpt-skin]', reason);
```

`[가정]` 콘텐츠 스크립트의 `console.warn` 이 이 목록에 수집된다.
사용자가 붙여준 스택(`health.js:34 (note)` → `soft` → `index.js:80`)이 그 목록의 표시 형식이었고,
그건 예외가 아니라 **우리가 찍은 경고**였다.

그래서 **이미 고친 문제의 경고가 계속 떠 있었다.** 제거 후 재설치하면 목록이 비니
"제거해야만 사라진다"가 성립한다 — 코드가 고쳐졌는지와 무관하게.

### 수정

일상 경고는 콘솔에 `console.debug` 로만 남긴다. 경고는 이미 **터미널 스크롤백**과 **배지**로 보인다.
`console.error` 는 두 곳만 남겼다 — 모듈 누락(preflight)과 핸들러 예외. 둘 다 진짜 결함이다.

### 검증 방법

`chrome://extensions` → gpt-skin → 오류 → **모두 지우기**.
그 뒤 페이지를 새로고침해서 오류가 **다시 생기는지** 본다.
다시 안 생기면 남아 있던 건 과거 기록이다.

## D. "지금 도는 게 새 코드인가"를 확인할 방법이 없었다 — 우리 결함

A 와 B 때문에 "고쳤는데 왜 그대로지?"가 반복되는데, 확인할 수단이 없었다.
추측으로 풀다 보니 제거 후 재설치가 유일한 확실한 수단이 됐다.

### 수정

빌드 스탬프를 넣었다.

```js
var GT_BUILD = '2026-09-01 12:38';
```

터미널 부팅 줄과 `:version` 에 찍힌다.

```
[info] gpt-skin 0.1.0 · build 2026-09-01 12:38 — :help 로 명령, ^` 로 원본 토글
```

**소스를 고쳤는데 이 값이 그대로면 확장이 다시 로드되지 않은 것이다.** 추측할 일이 없어진다.

## 올바른 절차

```
1. 소스 수정
2. chrome://extensions → gpt-skin 의 ↻
3. 대상 탭 새로고침          ← 이게 빠지면 고아 스크립트가 남는다
4. 부팅 줄의 build 값 확인 (또는 :version)
5. 오류 목록이 거슬리면 "모두 지우기"
```

**제거 후 재설치는 필요 없다.** 3번과 5번이 그동안 빠져 있었을 뿐이다.

| 바꾼 것 | 필요한 조치 |
|---|---|
| 무엇이든 (매니페스트·콘텐츠 스크립트·서비스 워커) | **↻ + 탭 새로고침** |
| 옵션 화면만 | 옵션 탭 새로고침 |

## 앞선 문서의 오류 — 두 번 틀렸다

1. 2026-08-31 첫 판: "콘텐츠 스크립트 내용만 고쳤으면 페이지 새로고침으로 충분" → 측정으로 정정 (A)
2. 정정판: "↻ 누르고 페이지 새로고침" → **↻ 만으로 끝난 것처럼 읽히게 썼고,
   열려 있는 탭의 고아 스크립트 문제를 아예 몰랐다** (B)

두 번 다 **측정 없이 단정한 것**이 원인이다. 이번엔 코드 전수 조사로 확인했다.

## 후속 (2026-09-01) — 조용히 물러나면 원본 UI 를 오해한다

해체가 잘 되는 것까지는 좋았는데, **아무 말 없이 사라지니 그 뒤가 문제였다.**

"사이드바가 안 닫힌다"는 신고를 받고 조사했더니 DOM 상태가 이랬다.

```
호스트존재: false      페이지스타일존재: false      클래스: (gpt-skin-on 없음)
```

터미널이 이미 물러난 뒤였고, 화면에 보이던 건 **원본 ChatGPT 사이드바**였다.
원본은 넓은 창에서 밀어내기 레이아웃이라 대화를 골라도 닫히지 않는다 —
그걸 우리 기능이 고장 난 걸로 읽은 것이다. 조사하는 나도 한참 헤맸다.

### 고침 1 — 물러났음을 눈에 보이게

우측 하단에 작게 띄운다.

```
gpt-skin 이 물러났다 (확장이 다시 로드됨).
지금 보이는 건 원본 UI 다 — 페이지를 새로고침해라.
```

### 고침 2 — pagehide 해체를 제거

`pagehide` 에서도 해체하고 있었다. **이득이 없고 위험만 있다.**

- 진짜 언로드라면 문서가 어차피 사라지므로 정리할 이유가 없다
- **bfcache** 로 들어간 것이라면 페이지가 되살아나는데 우리는 이미 자폭한 뒤다.
  disposer 를 다 비웠으니 돌아올 방법도 없다

이제 해체는 **'확장이 다시 로드됐다'는 신호 하나에만** 반응한다.
